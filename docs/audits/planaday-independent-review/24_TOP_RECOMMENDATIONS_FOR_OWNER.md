## Decision for the next development batch

Fund a bounded, verifiable repair release for writes, attachments, restore, authentication and runtime trust, followed by focused mobile and export repairs. Ask for proof of two-device hashes, explicit replacement restore, 1,000 overlapping write cases and a physical mobile keyboard record. Keep the legacy storage IDs and app data. The highest-value candidate specification additions define durable success, data scope, versioned operation and provenance. Their presence in the owner's master specification remains unknown until reviewed. Defer general-purpose compiler, broad Office/CAS parity, public marketplace and autonomous AI. ## Independent product assessment

| Question | Answer |
|---|---|
| What can it do now? | The build and 47 repository tests demonstrate a functional planning and record kernel, with calendar, notes, time tools, kitchen, Lab and creative workspaces. End-to-end acceptance varies. |
| Strongest capabilities? | Local record persistence, shared task and kitchen actions, a rich calendar model, core numerical helpers and Notes selection under controlled inputs. |
| Weakest capabilities? | Atomic write guarantees, multi-device attachment hydration, recovery/rebind assurance, unvisited offline loading, office interchange and narrow mobile layouts. |
| Which can expand most? | Typed links, scheduling, Notes search, Lab traceability, spreadsheet and presentation interoperability, Game balance and Book continuity. |
| What is missing? | General toolchain/compiler or interactive debugger and deck import were not found. App-layer authorization and second-client attachment hydration are missing safety/reliability functions. |
| What is missing from the master specification? | Unknown without an authoritative copy. Candidate additions include verified recovery and blob readiness, typed edges, trusted execution and versioned offline assets. |
| How can it be easier to use? | Offer Planner Lite, a mobile detail flow, predictable Save/Sync status, keyboard-first palette and one obvious view for daily work. |
| How can it be more customizable? | Declarative workspace templates, typed fields, saved filters, previewable automation, per-device layouts and scalable text. |
| How can it look better? | Standardize responsive spacing and group toolbars, maintain the paper look, improve focus/labels, and choose styles appropriate to professional workspaces. |
| How can it be more efficient? | Partition reads and queries by scope, paginate sync and limit whole-buffer parsing. Move tested repeated operations into reusable services. |
| What improves phones? | Sticky primary actions, one-column File Hub, keyboard-safe Notes and native capture/permission feedback. |
| What improves desktop? | Search shortcuts, pane layouts, independent history/inspector, printable docs and safe external-tool handoff. |
| What makes Lab outstanding? | Each sample, method, analysis and result links together with custody, reviewed calculations, inventory movements and clearly scoped access. |
| What makes Game Studio outstanding? | Version design entities and simulation inputs, track playtests and assets and record build evidence within the same project. |
| What makes Book Studio outstanding? | Scene-based drafts, binder and chronology, attributable character links, version compare and checked publishing exports. |
| What makes office productivity outstanding? | Accurate supported spreadsheet formulas and file exchange, PDF/document review and live versus frozen figure provenance. |
| What makes planner outstanding? | Stable layer anchors, tablet stylus ergonomics, visual templates, page fitting and printable export with keyboard control. |
| What advances knowledge management? | Stable record links, scope-aware search, saved views, attachment retrieval and decision/outcome history. |
| What advances math/science? | Reviewed reference datasets, dimension-aware calculations, explicit tolerances, units, uncertainty assumptions and reusable worksheet results. |
| What could outperform competitors? | Reduce duplicate entry across scheduling, records, evidence and specialist views while retaining local data and recoverability. |
| What could be distinctive? | Personal history with explicit scopes, living documents with frozen evidence, backup proof and calibrated scheduling. |
| What should share a system? | Durable record mutations, typed links, attachments, scoped search, layouts, backups and alert routing. |
| Which features should communicate? | Start with task/time views, Lab execution and purchasing, recipe inventory, media references, Book/Game relationships and analysis→report. |
| What decisions constrain expansion? | All-record UI subscriptions, full-record deltas, weak write boundaries, inconsistent export calls, title-based relationships and network trust. |
| What architecture supports growth? | Local-first modular domains with versioned data schemas, intent commands, durable queue, isolated services and permissioned graph. |
| Best relatively easy improvements? | Fix argument order in exports, responsive panels, explicit names and version alignment with CI. |
| Best major investments? | Reliable save and sync recovery, typed links, scoped authorization, editor architecture and validated Lab vertical slices. |
| Which expansions give poor value now? | Complete office or engine parity, embedded terminal/toolchain, CAS breadth, global marketplace and external AI processing. |
| What comes next? | R0 atomic writes, attachment transfer, recovery and authorization with test-first release gating. |
| What could it ultimately become? | A local-first planner and cross-domain workbench with user-owned data that can support professional, educational and creative routines. |
