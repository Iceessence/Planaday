# Innovation and competitive advantage

Planaday could compete through the combination of offline ownership, a single record shared across workflows, and optional specialist views. Scheduling tools, note graphs, local journals and LIMS already provide important adjacent functions. Competitive uniqueness below is a product hypothesis based on the [vendor review](14_COMPETITOR_ANALYSIS.md).

| Concept | Value, operation and reuse | Constraint and investment decision |
|---|---|---|
| Personal timeline and configurable historical comparisons | Show selected tasks, photos, meals and outcomes by period, with drill-through to source. Reuse temporal records, ledger, relationships and reports. | Separate personal and lab scopes, opt in per input and avoid causal inference. Prototype after record permissions. PF-39 |
| Personal time calibration | Estimate available time and task duration from a local, filtered sample. Explain inputs, uncertainty and manual adjustments. Reuse timer, task type and schedule. | Treat sparse data as low confidence, protect sensitive periods and preserve overrides. Run holdout comparisons against current scheduler. PF-49 |
| Live document with frozen evidence | Retain live relationships and freeze a reviewed calculation, figure and note as a verifiable snapshot. Reuse interoperable export, attachments and typed links. | A frozen version must be stable and authorized. A high-value lab/report pilot is worth doing after export repairs. PF-40 |
| Relationship explorer with scope preview | Explore tasks, studies, lab samples, scenes, assets and decisions through typed, permission-aware edges. Add an accessible list and saved branch view. | Prevent hidden context exposure and bound graph neighborhoods. Existing graph applications are useful comparisons, with different typical record scopes. PF-43 |
| Adaptive workspaces without moving the user's priorities | Choose workspace based on time/task and let users pin view choices across changes. Reuse quick glance, profiles, settings and schedule. | Context selection is local and explainable. Run a manual-switch benchmark first. PF-44 |
| Decision journal with an outcome trail | Capture planned alternatives, confidence and expected outcomes. Attach dates and observed outcomes with original decisions preserved. Useful across life, book, game and lab projects. | Avoid retrospective overwrite and omit sensitive data by default when sharing. A focused template can pilot this early. PF-41 |
| Verifiable recovery rehearsal | Produce a dated proof of what a backup can reopen and which records/blobs failed. Reuse backup, dry run, hash and restore states. | Isolate restore/check storage, redact receipts and make small device manifests efficient. High priority for a self-host pilot once core restore works. PF-42 |
| Approved cross-workspace briefing | Generate an owner-controlled daily dashboard pulling limited, permissioned signals from Lab, personal calendar and writing milestones. Reuse view templates and scope rules. | Demonstrate each metric's origin, prevent projecting private details into work. Test simple dashboard controls before adaptive automation. PF-39/44/47 |
| Reproducible creative scenario notebook | Pin a game balance scenario's inputs or a book continuity check to a review record and connect later outcomes. Reuse typed links, file snapshots and calc provenance. | Game/fiction data must remain local unless deliberately shared. Prove one domain before generalizing tool. PF-26/28/33/40 |
| Portable workspace kits | Opt-in package holding layout, schema and disabled-by-default automation with inspectable provenance, without including private records. | Begin with local import/export. A public marketplace entails additional moderation, trust and maintenance. PF-36/45 |
| Source-linked local assistance | Suggest task/summary text with provenance and explicit approval, with all processing controlled by owner and scoped to chosen inputs. | Validate local/off behavior, cost and performance. Defer external processing and autonomous side effects unless separately approved. PF-35 |

Potential consolidation: render tasks in planning, project and lab views from the same identifiers. Render documents, photos and original attachments with one file reference service. Reuse scheduling for timers, reminders and instrument operations, with distinct event semantics. Use templates for collectors, household utilities and study journals. Existing specialized fields and user data remain mapped and accessible through their workflows. [Consolidation and migration](21_EXPANDED_PRODUCT_ROADMAP.md)
